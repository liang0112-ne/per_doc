# per_doc 项目重建方案

> 基于 MinDoc（Go + Beego）核心能力重构建的轻量级文档管理系统
> 版本：v1.0　|　状态：设计稿　|　日期：2026-11-24

---

## 1. 项目概述

### 1.1 项目定位

**per_doc** 是一个面向个人 / 小团队的轻量级文档管理与录入系统，提供「文档库 → 目录树 → Markdown 文档」的完整闭环。

核心价值：

- **开箱即用**：单进程 + 单文件数据库，零外部依赖，一条命令启动
- **专注录入**：把 MinDoc 的企业级复杂度（团队、成员协作、权限矩阵、审核流、评论体系）全部剥离，只保留文档本身的组织与编辑
- **技术栈现代化**：Python 3.12 + FastAPI + SQLAlchemy 2.0 + Vue 3 + TypeScript，摆脱 CGO 编译与老旧 jQuery 依赖

### 1.2 与原项目的关系

| 项目 | 定位 | 技术栈 | 处置 |
|---|---|---|---|
| `mindoc-master` | 企业级文档协作平台 | Go 1.23 + Beego + jQuery | **参照实现**，保留作为业务规则参考，不参与新系统运行 |
| `per_doc` | 轻量级文档录入系统 | Python + Vue 3 | **全新实现**，数据表结构与 `mindoc` 保持兼容以支持存量迁移 |

`mindoc-master/` 目录保留在仓库中，用于：
1. 业务规则查阅（权限判定、搜索分词、导出流程、文档树排序算法）
2. 数据迁移时的字段映射依据
3. 存量数据导入的对照测试

### 3.2 关键选型理由

**为什么 FastAPI 而不是 Flask / Django**
- 需要自动生成 OpenAPI 契约，供前端并行开发
- 原 Go 项目是 Beego MVC，`controllers/` 里大量 `this.Data` / `this.Render` 是「服务端渲染模板」的产物；FastAPI + Vue SPA 彻底消除这类代码
- 自带 Pydantic 校验，等价于原项目的 `conf` 枚举 + 手工校验

**为什么 SQLite 仍作为默认**
原项目用 `mattn/go-sqlite3`（CGO），导致：
- CentOS7 需要 musl 单独编译（README 明确说明）
- 交叉编译困难

Python 标准库自带 `sqlite3`，彻底消除该问题。SQLAlchemy 抽象层保证后续可无痛切换 PostgreSQL。

**搜索策略升级**
原实现是 `LIKE '%keyword%'` + jieba 分词拼关键词（`models/DocumentSearchResult.go`）：

```
keyword = "%" + strings.Replace(keyword, " ", "%", -1) + "%"
```

性能随数据量线性劣化。per_doc 采用三级策略：

| 阶段 | 方案 | 适用场景 |
|---|---|---|
| 方案 A（默认） | SQLite FTS5 虚拟表 | 单机、零依赖、中文需 `trigram` 或 `unicode61` + 预分词 |
| 方案 B（推荐） | PostgreSQL `tsvector` + GIN 索引 | 多用户、需要中文分词（zhparser） |
| 方案 C（可选） | Meilisearch / Elasticsearch | 文档量 > 10 万，或需要拼写纠错 / 同义词 |

分词器保留 Python 版 `jieba`（原 Go 版用 `gojieba` C++ 扩展），在写入时对 `title + markdown` 做预分词并写入 FTS 表。

## 4. 数据库设计

### 4.1 设计原则

1. **表名前缀** 保留 `md_` 兼容前缀（可通过 `db_prefix` 配置），便于存量数据直接导入
2. **字段命名** 与原项目完全对齐（原项目用 `orm:"column(xxx)"` 显式指定列名），保证迁移脚本零歧义

4. 保留 `md_` 前缀的同时，表结构做适度精简（删除无用字段）

### 5.2 分层约定

| 层 | 职责 | 禁止 |
|---|---|---|
| `api/` | 解析请求、校验参数、调用 service、组装响应 | 不写业务逻辑、不直接写 ORM 查询 |
| `services/` | 业务规则、事务边界、权限判定 | 不感知 HTTP（不返回 `HTTPException`） |
| `models/` | 表结构映射 | 不写业务逻辑 |
| `schemas/` | 请求/响应数据契约 | 不含业务逻辑 |

**事务边界统一在 service 层**：

```python
# app/services/document_service.py（示意）
from sqlalchemy.orm import Session

def create_document(db: Session, space_id: int, payload: DocumentCreate, member_id: int) -> Document:
    """创建文档：分配 identify、计算同级排序、写入首版历史。"""
    doc = Document(
        document_name=payload.name,
        identify=generate_identify(),
        space_id=space_id,
        parent_id=payload.parent_id,
        order_sort=next_order_sort(db, space_id, payload.parent_id),
        markdown=payload.markdown,
        content=render_markdown(payload.markdown),
        member_id=member_id,
        modify_at=member_id,
        version=1,
    )
    db.add(doc)
    db.flush()
    write_history(db, doc, action="create", action_name="创建文档")
    db.commit()
    db.refresh(doc)
    return doc
```

### 5.3 认证设计

#### 登录流程

```
POST /api/auth/login  { account, password }
        │
        ├─ 查 md_members，校验 status == 0
        ├─ Argon2id 校验密码
        ├─ 写 Session（cookie: per_doc_session, HttpOnly, SameSite=Lax）
        ├─ 更新 last_login_time
        └─ 返回 { user: { member_id, account, real_name, avatar } }
```

#### Session 方案

- 存储：`itsdangerous` 签名的 Cookie（默认），或 Redis（`SESSION_BACKEND=redis`）
- 内容：`{"member_id": int, "login_at": ts}`
- 有效期：7 天（`SESSION_MAX_AGE`）
- CSRF：写操作要求 `X-CSRF-Token` 头，值由 `GET /api/auth/csrf` 下发

#### 密码策略

| 规则 | 值 |
|---|---|
| 哈希算法 | Argon2id（`argon2-cffi`） |
| 最小长度 | 8 |
| 复杂度 | 至少包含字母和数字 |
| 登录失败锁定 | 5 次失败锁定 15 分钟 |

> 原项目使用 Beego 提取的 `Md5Crypt`（`utils/cryptil/cryptil.go`），MD5 已不安全，重构改为 Argon2。若需兼容存量用户，首次登录时用旧 hash 校验成功即自动升级为 Argon2。

### 5.4 权限模型（极简）

per_doc 只有两种身份：

| 身份 | 判定 | 权限 |
|---|---|---|
| **登录用户** | Session 有效 | 读写全部文档库与文档；管理自己的账号；进入后台 |
| **游客** | 无 Session | 只读公开（`is_private = 0`）的文档库与文档；不可见管理页 |

判定逻辑：

```python
# app/core/deps.py（示意）
from fastapi import Depends, HTTPException, status
from sqlalchemy.orm import Session

async def current_user(
    db: Session = Depends(get_db),
    session: dict = Depends(read_session),
) -> Member:
    member_id = session.get("member_id")
    if not member_id:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "未登录")
    member = db.get(Member, member_id)
    if not member or member.status != 0:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "账号不可用")
    return member

async def current_user_optional(
    db: Session = Depends(get_db),
    session: dict = Depends(read_session),
) -> Member | None:
    """游客可访问的接口使用此依赖。"""
    member_id = session.get("member_id")
    if not member_id:
        return None
    return db.get(Member, member_id)
```

访问密码保护（替代原项目的 `BookPassword` + `PrivateToken`）：

```
GET  /api/spaces/{key}/access        -> 校验访问密码，成功后写入 Cookie
```

```typescript
  const auth = useAuthStore()

  }

  return true
})
```

## 9. 部署方案

### 9.1 方式一：源码运行（开发）


### 9.2 方式二：Docker Compose（推荐生产）

```yaml
# docker-compose.yml
version: "3.8"
services:
  api:
    build:
      context: ./backend
    container_name: per_doc_api
    restart: always
    ports:
      - "8181:8181"
    volumes:
      - ./backend/data:/app/data
    environment:
      - PER_DOC_DB_ADAPTER=sqlite
      - PER_DOC_DB_PATH=/app/data/per_doc.db
      - PER_DOC_SECRET_KEY=${PER_DOC_SECRET_KEY}
      - PER_DOC_UPLOAD_DIR=/app/data/uploads
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8181/api/health"]
      interval: 30s
      timeout: 5s
      retries: 3

  web:
    build:
      context: ./frontend
      args:
        - VITE_API_BASE=/api
    container_name: per_doc_web
    restart: always
    ports:
      - "80:80"
    depends_on:
      - api
```

### 9.3 方式三：单容器（前后端合一）

## 10. 存量数据迁移

### 10.1 迁移范围

从 `mindoc-master` 的 `md_` 表导入 per_doc：

| 原表 | 目标 | 备注 |
|---|---|---|
| `md_members` | `md_members` | 密码保留旧 hash，首登升级为 Argon2 |
| `md_books` | `md_spaces` | `book_name` → `space_name`；`item_id` → `group_name` 查 `md_itemsets` |
| `md_documents` | `md_documents` | `book_id` → `space_id`；`identify` 规则校验（`[a-z][a-zA-Z0-9_.-]*`） |
| `md_document_history` | `md_document_history` | 直接迁移 |
| `md_attachment` | `md_attachments` | `book_id` → `space_id`；文件需从 `uploads/` 拷到新目录 |
| `md_options` | `md_options` | 过滤掉已废弃的键 |
| `md_logs` | `md_logs` | 字段名不同，做映射 |

**不迁移**：`md_relationship`、`md_teams`、`md_team_member`、`md_team_relationship`、`md_comments`、`md_comment_votes`、`md_blogs`、`md_label`、`md_templates`、`md_auth2_accounts`、`md_dingtalk_accounts`、`md_workweixin_accounts`、`md_member_token`、`md_t_content_reverse_index`、`md_itemsets`（降级为字段）。

### 10.2 迁移脚本流程

```text
1. 读取源 SQLite / MySQL 连接串
2. 逐表 SELECT，字段映射 + 类型转换
3. identify 冲突时追加随机后缀
4. 附件：复制 uploads/ 下文件到新目录，重写 http_path
5. 写入目标库（幂等：已存在则跳过）
6. 输出迁移报告：各表导入/跳过/失败条数
```

### 10.3 校验清单

- [ ] 文档总数与源库一致
- [ ] 随机抽取 10 个文档，Markdown 内容逐字节比对
- [ ] 文档树层级与排序一致（对比 `/api/spaces/{key}/tree` 输出）
- [ ] 所有附件可下载且 MD5 一致
- [ ] 存量用户能用原密码登录
- [ ] 搜索结果条数与原库基本一致

## 12. 风险与对策

| 风险 | 等级 | 影响 | 对策 |
|---|---|---|---|
| **Markdown 渲染差异** | 高 | 原项目用 blackfriday + 自定义扩展（代码高亮主题、目录锚点、附件链接改写），Python 侧行为可能不一致 | P4 阶段先做渲染一致性测试集：用原项目导出的 20 篇文档做 golden test，比对 HTML 输出 |
| **中文搜索效果** | 中 | jieba 分词 + FTS5 组合效果需实测 | 准备 100 条真实查询做对比评测；若 FTS5 效果不佳则切换方案 B（PostgreSQL） |
| **前端设计还原度** | 中 | ASCII 设计图到实际实现有偏差 | 每个页面先出静态 HTML 原型评审，再接接口 |
| **存量数据 identify 冲突** | 低 | 原库可能有重复 identify | 迁移脚本自动加后缀并记录映射表 |
| **PDF 导出** | 低 | WeasyPrint 与 wkhtmltopdf 渲染差异大 | 导出功能默认关闭，作为可选增值项；若开启则只保证基本排版 |
| **单机 SQLite 并发** | 低 | 写并发有限 | 个人/小团队场景足够；提供 PostgreSQL 配置作为扩展 |
| **原项目功能缺失导致不满** | 中 | 用户可能期望团队协作 | 文档中明确列出裁剪清单与原因，二期再评估 |

### 12.1 明确不做的事

- 不实现富文本（Word）编辑器 —— 专注 Markdown
- 不实现协同编辑（多人同时编辑）—— 用乐观锁规避冲突
- 不实现评论/点赞/博客 —— 非录入核心
- 不实现移动端 App —— 响应式 Web 足够
- 不追求与原项目 UI 一致 —— 全新设计
